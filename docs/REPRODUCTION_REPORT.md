## 2. 이동 가능한 구성 및 새 환경 실행 절차 (Clean Environment)

새로운 PC 또는 임의의 빈 디렉터리에서 프로젝트를 독립적으로 복제하고 실행하는 절차입니다. 특정 사용자 환경의 절대 경로(`C:\Users\...`)나 비밀 설정값에 일체 의존하지 않으며, 이식 가능한 표준 절차로 동작합니다.

### 2.1. 사전 준비 환경
- **Node.js**: `Node.js 22 ~ 24` (`>=22.0.0 <=24.x` 호환, 수업 공식 기준 및 권장 버전: `v24.19.0`, 실제 확인: `v24.13.0`)
- **Git**: `2.x` 이상
- **터미널**: Windows PowerShell (또는 bash)

### 2.2. 새 빈 폴더에서의 설치 및 실행 절차

```powershell
# 1. 원하는 임의의 작업 디렉터리로 이동한 뒤 저장소를 복제합니다.
# (예: C:\workspace 또는 ~/projects 등 본인 환경의 작업 경로)
Set-Location -Path "<작업_디렉터리_경로>"
git clone https://github.com/jinyeongjang/choi-bujang-secret-vault.git fresh-alekov
Set-Location -Path "fresh-alekov"

# 2. 복제된 저장소의 기본 브랜치(main) 최신 릴리스 커밋 상태를 확인하고 체크아웃합니다.
# (심판 공식 안내에 따라 현재 제출본을 가리키는 정확한 릴리스 태그 v0.2.11-student-verified로 체크아웃합니다)
```

- **터미널 출력 정상 신호**:
  ```text

  ```
- **브라우저 접속 주소**: `http://127.0.0.1:5189`

## 3. 학생 데이터 보존 계획 및 비밀 파일 제외 백업 (Data Preservation Plan)

본 프로젝트는 데이터 유실을 방지하고 보안 비밀값의 유출을 원천 차단하기 위해 엄격한 데이터 보존 및 백업 규정을 적용합니다.

### 3.1. 보존할 데이터 목록 (xdr/alerts.log 포함)
- **학생 구현 소스코드**: `student/extension.mjs` (UI 렌더링 확장 함수 전체)
- **시작 틀 및 매니페스트**: `package.json`, `package-lock.json`, `aleph.config.json`, `.on-starter-manifest.json`
- **시스템 실행 설명서 및 재현 문서**: `docs/*`, `README.md`
- **Git 버전 히스토리**: 13~22단계의 모든 커밋 로그 (`git reset --hard` 금지)
- **과거 XDR 보안 경보 및 대응 기록 (`xdr/alerts.log`)**:
  - 이전 단계(무차별 대입, 웹 인젝션, CVE 등)에서 시뮬레이션된 사건 탐지 및 대응 규칙 동기화 이력이 기록된 로컬 런타임 로그 파일입니다.
  - 과거 보안 사건 대응 이력의 사후 감사(audit) 및 아카이빙 목적으로 보존 대상에 포함합니다.

### 3.2. 백업 제외 대상 (보안 비밀값 및 임시 파일)
- **개인 자격 증명 및 토큰 파일**: `.env`, `.env.*` (개인 비밀번호, API 키, 서비스 토큰, `.env.local` 등 모든 비밀 환경 파일)
- **외부 패키지 설치물 및 캐시**: `node_modules/`
- **임시 검증 및 번들 파일**: `artifacts/`, `bundle-notes.json`

### 3.3. 백업 절차에서 비밀 설정 파일 제외 방법
Git의 `.gitignore`는 Git 추적만 제한하므로, 단순한 폴더 전체 복사 시 로컬의 비밀 파일(`.env`, `.env.*`)이 함께 복사되는 보안 위험이 발생합니다. 따라서 백업 수행 시에는 반드시 비밀 설정 파일(`.env`, `.env.*`)을 명시적으로 제외하고 프로젝트를 백업합니다.

```powershell
# [방법 1] robocopy로 .env와 node_modules만 제외하고 xdr/alerts.log를 포함하여 프로젝트 외부 백업
robocopy . "<프로젝트_외부_백업_디렉터리>" /E /XF .env .env.* /XD node_modules .git
# -> .env 및 .env.local 등 모든 비밀 설정 파일이 안전하게 제외되며, xdr/alerts.log는 사후 감사용으로 <백업_디렉터리>\xdr\alerts.log에 보존됩니다.

# [방법 2] Git 아카이브 기능을 이용해 추적 소스와 xdr 로그를 ZIP으로 안전하게 백업 (비밀 파일 원천 배제)
git archive --format=zip --output="<프로젝트_외부_백업_디렉터리>\vault-backup.zip" HEAD
```

### 3.4. 복원 절차 및 실제 코드 아키텍처 대조 (호스트 어댑터 동작 기준)
1. **파일 복원**: 백업 사본 또는 저장소 복제본을 대상 작업 디렉터리에 복원합니다.
2. **사후 감사 로그 배치 위치**: 백업된 로그 파일은 프로젝트 루트 기준 **`xdr/alerts.log`** 위치에 보존 및 배치합니다.
3. **실제 실행 코드와 복원 동작 대조**:
   - 현재 서버 시작 코드(`src/server.mjs`) 및 호스트 어댑터(`student/engine-adapter.mjs`)는 로컬 디스크의 로그 파일을 읽어 상태를 복원하는 동작을 포함하지 않으며, 인메모리/네트워크 기반으로 동작하는 **무상태(stateless) 클라이언트 에이전트** 구조입니다.
   - 따라서 `xdr/alerts.log` 파일의 보존은 과거 보안 조치 이력에 대한 **사후 감사(audit) 및 기록 보관 목적**이며, 앱 재기동 시 엔진 어댑터가 이 파일을 파싱하여 화면에 과거 이벤트를 자동으로 재로드하거나 복원하지 않습니다.
   - 앱 기동 시 표출되는 보안 사건 및 식별 상태는 호스트 어댑터의 인터페이스 함수(`readEvents`, `readIdentity`, `readApps` 등)를 통해 실시간으로 연결된 SDP 호스트로부터 동적으로 공급됩니다.

### 3.5. 복구 후 별도 자격 재인가 절차 (Credential Re-authorization)
백업 사본으로 프로젝트를 복원하거나 새 환경으로 이전한 경우, 보안 원칙에 따라 `.env` 파일과 세션 자격 증명이 존재하지 않습니다. 따라서 다음과 같은 공식 인가 절차를 수행해야 합니다.

1. **환경 템플릿 확인**: 프로젝트에 제공된 `.env.example`을 참고하여 필요한 환경변수 구조를 확인합니다.
2. **AI 연결 재인가**:
   - 로컬 앱 서버 기동(`npm start`) 후 브라우저(`http://127.0.0.1:5189`)의 AI 연결 관리 메뉴로 이동합니다.
   - 「연결 시작」을 통해 새 연결 ID를 발급받고, 제공된 승인 링크에서 관리자 승인을 획득하여 자격을 재설정합니다.
3. **백엔드 API 연동 재인가**:
   - 1~12단계 백엔드 API 연동이 필요한 경우, Supabase 관리자 포털에서 직접 정규 서비스 롤 키 또는 세션 토큰을 설정합니다. (비밀값은 코드나 커밋에 절대 입력하지 않습니다.)

### 3.6. 복구 한계와 제한 사항 (Recovery Limits)
- 소스코드(`student/extension.mjs`), 프로젝트 설정, 매니페스트, 공식 문서, Git 버전 기록은 백업본을 통해 100% 완전 복구가 가능합니다.
- **로컬 로그 런타임 자동 복원 없음**: 현재 호스트 어댑터 구현상 로컬 파일(`xdr/alerts.log`)을 읽어 인메모리로 복원하는 로더가 없으므로, 과거 보안 경보 및 차단 규칙이 화면에 자동으로 복원되지 않습니다. (동적 호스트 연동 시에만 실시간 사건이 수신됨)
- **세션 및 자격증명 복구 불가**: 브라우저의 활성 로그인 세션, 일회성 발급 토큰, 메모리 내 인메모리 연결 상태는 복원되지 않으며 복구 후 별도 자격 재인가 절차를 거쳐야 정상 동작합니다.

> - **연결 없음**: 로컬 서버는 정상이나 기존 상위 SDP/XDR 엔진이 연결되지 않아 화면에 의도된 미연결 안내가 출력되는 상태
> - **예제 자료**: `--demo` 플래그로 기동하여 표출된 모의 데이터는 실제 연결 성취가 아니므로 '재현됨'으로 간주하지 않고 비고에 명시

## 6. 지원 범위 및 기다림 (UNV) 목록

본 릴리스 시점에서 구현 및 검증이 완료된 범위와 향후 환경 연동을 위한 대기(UNV: Unverified) 항목은 다음과 같습니다.

### 6.1. 지원 및 검증 완료 범위
- **버전 체계 일치 및 정직한 안내**:
  - 클라이언트 패키지 매니페스트(`package.json`): `alekov-client-starter` `0.2.11`
  - 로컬 앱 서버 런타임(`src/server.mjs`): API 메타데이터 `starterVersion: 0.1.0` 및 `/api/diagnostics`의 component version `0.1.0` 내보냄
  - 이 두 표시는 상충하는 오류가 아니라, 패키지 배포 버전(0.2.11)과 서버 내부 API 메타데이터 기본 규격(0.1.0)의 차이임을 문서에 투명하게 명시함
- **플랫폼 환경**: Node.js 22~24 (Windows 10/11 환경 루프백 바인딩)
- **독립 실행**: 외부 npm 패키지 의존성 없이 `src/server.mjs` 단독 기동
- **UI 컴포넌트**: 13~20단계 8개 렌더링 함수의 상태(허용, 거부, 확인불가, 연결없음, 빈 상태 등) 분리 표출
- **문서화**: 설치, 실행, 시스템 구성도, 장애 처리 절차, 새 환경 재현 절차 문서 구비
- **데이터 보존 및 감사 로그 아카이빙**: 학생 구현 코드, 설정, 문서의 안전한 백업(.env 배제) 및 과거 대응 기록(`xdr/alerts.log`)의 감사 목적 보존 정의

### 6.2. 기다림 (UNV) 목록
1. **운영 SDP 호스트 실시간 연동**: 원격 상용 SDP 컨트롤러와의 실제 인증 패킷 교환은 로컬 검수 환경 밖으로 미확인 유지.
2. **외부 상용 AI 유료 API 연동**: OpenAI 등 외부 상용 LLM 서비스에 대한 실제 결제 키 발급 및 실시간 모델 호출은 미확인 상태 유지.
3. **19단계 방화벽 실집행 연동**: 네트워크 장비에 대한 실제 패킷 차단 룰셋 적용은 가상 격리 상태로 실집행 미연결 유지.
4. **외부 라이브 OSV 데이터베이스 실시간 통신**: 로컬 패키지 매니페스트 분석 외에 실시간 인터넷 OSV API 라이브 피드 질의는 미확인 상태 유지.
