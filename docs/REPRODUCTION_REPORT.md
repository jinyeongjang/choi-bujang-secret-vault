## 2. 이동 가능한 구성 및 새 환경 실행 절차 (Clean Environment)

새로운 PC 또는 빈 폴더에서 프로젝트를 독립적으로 복제하고 실행하는 절차입니다. 로컬 절대 경로나 비밀 설정값에 의존하지 않으며, loopback(`127.0.0.1:5189`)과 기본 템플릿만으로 기동할 수 있습니다.

### 2.1. 사전 준비 환경
- **Node.js**: `Node.js 22 ~ 24` (`>=22.0.0 <=24.x` 호환, 수업 공식 기준 및 권장 버전: `v24.19.0`, 실제 확인: `v24.13.0`)
- **Git**: `2.x` 이상
- **터미널**: Windows PowerShell (또는 bash)

### 2.2. 새 빈 폴더에서의 실행 순서

```powershell
# 1. 기존 폴더 외부에 새로운 작업 디렉터리를 만들고 저장소를 복제합니다.
Set-Location -Path "C:\Users\wlsdu\Desktop"
git clone https://github.com/jinyeongjang/choi-bujang-secret-vault.git fresh-alekov
Set-Location -Path "fresh-alekov"

# 2. 검증 대상 최종 커밋으로 체크아웃합니다. (또는 기본 main 브랜치 유지)
git checkout main
# 또는 특정 커밋 지정: git checkout <제출_40자리_커밋>

# 3. 학생 구현 UI 문법 무결성을 점검합니다.
npm run check
# -> 정상 결과: "node --check student/extension.mjs" 성공 (출력 오류 없음)

# 4. 앱 서버를 기동합니다. (PowerShell 실행 도구 또는 npm start)
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
# 또는: npm start
```

### 2.3. 정상 시작 신호 및 브라우저 확인
- **터미널 출력 정상 신호**:
  ```text
  케셰브 연결 확인: http://127.0.0.1:5189
  ```
- **브라우저 접속 주소**: `http://127.0.0.1:5189`
  - 접속 시 상단 헤더 메뉴(내 상태, 업무 앱, 보안 이벤트)와 진단, AI 연결, 패키지 취약점 섹션이 렌더링되며, 미연결 상태인 경우 "기존 서버와 연결되지 않았습니다." 또는 "연결 없음" 안내가 명확한 텍스트로 표출됩니다.

### 2.4. 종료 및 재실행 순서
1. **종료**: 실행 중인 PowerShell 콘솔에서 `Ctrl + C`를 누르고, 일괄 작업 끝내기 질문에 `Y`를 입력합니다.
2. **재실행**: 프로세스 종료 후 다시 `npm start`를 입력하여 서버가 다시 리슨되는지 확인합니다.

> [!CAUTION]
> 기존 작업 폴더에 존재하는 `.env` 파일이나 개인 인증 토큰을 새 폴더로 무작정 복사하지 마십시오. 시작 틀에 제공된 `.env.example` 설정을 기준으로 동작해야 하며, 비밀 값은 코드나 저장소에 포함되지 않습니다.

## 3. 학생 데이터 보존 및 백업 계획 (Data Preservation Plan)

본 프로젝트는 단계별 학습 과정과 사용자의 보안 상태 데이터를 안전하게 보존하고 복구할 수 있도록 다음과 같은 데이터 보존 규칙을 준수합니다.

### 3.1. 기존 작업 및 Git 기록 보존
- **비파괴 원칙**: 기존 1~12단계 작업 자산, 이전 커밋 이력, `.on-starter-manifest.json` 해시 기준 파일은 임의로 삭제하거나 덮어쓰지 않습니다.
- **`git reset --hard` 금지**: 이전 단계를 되돌리거나 정리할 때 작업 내역을 유실할 수 있는 파괴적 명령은 사용하지 않으며, 항상 변경 전 상태를 커밋하거나 브랜치를 보존합니다.

### 3.2. 데이터 백업 및 복원 절차
1. **로컬 백업**:
   - 프로젝트 최상위 폴더 전체를 프로젝트 외부 안전한 저장 경로(예: `C:\Users\wlsdu\Desktop\backup-vault`)로 주기적으로 복사하여 백업합니다.
2. **복원 절차**:
   - 새로운 환경이나 손상 발생 시 Git 원격 저장소(`origin/main`)에서 clone을 수행하거나 로컬 백업 사본을 통해 상태를 복구합니다.
   - 백엔드 메모 데이터의 경우 1~12단계에서 구현된 `/api/notes/restore` 엔드포인트를 통해 복원 요청을 수행할 수 있습니다.
3. **데이터 보존의 한계와 제한**:
   - API 키, 개인 토큰, 세션 쿠키 등 민감한 자격 증명은 보안 원칙상 Git 저장소나 백업 번들에 포함되지 않습니다.
   - 따라서 새 환경으로 복원한 후에는 공식 설정 화면 또는 로그인 절차를 통해 자격 증명을 재인가받아야 합니다.

## 6. 지원 범위 및 기다림 (UNV) 목록

본 릴리스 시점에서 구현 및 검증이 완료된 범위와 향후 환경 연동을 위한 대기(UNV: Unverified) 항목은 다음과 같습니다.

### 6.1. 지원 및 검증 완료 범위
- **플랫폼 환경**: Node.js 22~24 (Windows 10/11 환경 루프백 바인딩)
- **독립 실행**: 외부 npm 패키지 의존성 없이 `src/server.mjs` 단독 기동
- **UI 컴포넌트**: 13~20단계 8개 렌더링 함수의 상태(허용, 거부, 확인불가, 연결없음, 빈 상태 등) 분리 표출
- **문서화**: 설치, 실행, 시스템 구성도, 장애 처리 절차 문서 구비

### 6.2. 기다림 (UNV) 목록
1. **운영 SDP 호스트 실시간 연동**: 원격 상용 SDP 컨트롤러와의 실제 인증 패킷 교환은 로컬 검수 환경 밖으로 미확인 유지.
2. **외부 상용 AI 유료 API 연동**: OpenAI 등 외부 상용 LLM 서비스에 대한 실제 결제 키 발급 및 실시간 모델 호출은 미확인 상태 유지.
3. **19단계 방화벽 실집행 연동**: 네트워크 장비에 대한 실제 패킷 차단 룰셋 적용은 가상 격리 상태로 실집행 미연결 유지.
4. **외부 라이브 OSV 데이터베이스 실시간 통신**: 로컬 패키지 매니페스트 분석 외에 실시간 인터넷 OSV API 라이브 피드 질의는 미확인 상태 유지.
